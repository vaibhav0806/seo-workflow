# Cloudinary Cover Upload Design

Date: 2026-05-22
Project: seo-workflow

## Problem

The competitor SEO blog workflow can generate cover images through OpenRouter and attach them to content PRs, but the current generated `cover:` URL can point at private GitHub raw content. Reviewers correctly flagged that these URLs will not render publicly after publishing.

The workflow needs to upload generated cover images to a public image host automatically and write the public HTTPS URL into blog frontmatter.

## Decision

Use Cloudinary signed uploads as the default third-party image host. Cloudinary has a free plan and a straightforward server-side upload API that accepts image bytes or base64 data and returns a public `secure_url`.

ImageKit and Uploadcare remain reasonable future adapters, but Cloudinary is the first implementation because it has the smallest integration surface for the current Go workflow.

## Goals

- Upload OpenRouter-generated cover images automatically during the competitor content PR flow.
- Set `BlogPost.Cover` to the public Cloudinary `secure_url`.
- Avoid relying on private GitHub raw URLs for published cover images.
- Keep the workflow resilient: cover upload failures should not block the content PR when a default cover URL is configured.
- Keep configuration explicit through environment variables.

## Non-Goals

- Build a general media asset manager.
- Migrate existing blog covers.
- Add browser-side unsigned uploads.
- Add paid transformations or AI image editing through the host.
- Remove support for the existing `CONTENT_COVER_ASSET_BASE_URL` path immediately.

## Configuration

New optional environment variables:

- `CLOUDINARY_CLOUD_NAME`
- `CLOUDINARY_API_KEY`
- `CLOUDINARY_API_SECRET`
- `CLOUDINARY_UPLOAD_FOLDER`, default `createos/blog-covers`

Existing variables keep their meaning:

- `OPENROUTER_API_KEY`
- `OPENROUTER_COVER_MODEL`
- `CONTENT_DEFAULT_COVER_URL`
- `CONTENT_COVER_ASSET_BASE_URL`

Cloudinary upload is enabled only when all three required Cloudinary credentials are present.

## Architecture

Add a small upload boundary in `internal/contentrepo`:

- `CoverUploader` interface with `UploadCover(ctx, asset, slug) (string, error)`.
- Cloudinary implementation using signed server-side upload.
- No-op/fallback behavior remains in `cmd/worker/content_pr.go`.

The existing OpenRouter generator should continue returning generated image bytes and metadata. The worker decides how those bytes become a public URL.

## Data Flow

1. Build the blog draft with the configured default cover URL.
2. Validate that the content PR can proceed before generating or uploading a cover.
3. Generate a cover through OpenRouter when `OPENROUTER_API_KEY` and `OPENROUTER_COVER_MODEL` are set.
4. If Cloudinary credentials are present, upload the generated bytes to Cloudinary.
5. If Cloudinary returns a valid `secure_url`, assign it to `post.Cover`.
6. If Cloudinary is not configured but `CONTENT_COVER_ASSET_BASE_URL` is configured, preserve the current behavior of committing `covers/<slug>.<ext>` to the content repo and using that base URL.
7. If generation or upload fails, log the failure and keep the default cover URL.
8. Publish the blog PR.

## Cloudinary Request

Use `POST https://api.cloudinary.com/v1_1/{cloud_name}/image/upload`.

Use HTTP Basic Authentication with `api_key:api_secret` so the code does not need to manually generate signatures.

Upload as `multipart/form-data`:

- `file`: generated image bytes
- `asset_folder`: configured upload folder
- `public_id_prefix`: configured upload folder
- `public_id`: blog slug
- `overwrite`: `false`
- `resource_type`: image endpoint

Parse the response for:

- `secure_url`
- `public_id`
- optional `format`, `bytes`, and `created_at` for logging/tests

Only `secure_url` is required by the publishing workflow.

## Error Handling

- Missing Cloudinary credentials disables Cloudinary upload.
- Non-2xx Cloudinary responses return an error containing status and a short response body.
- Empty `secure_url` is treated as an upload error.
- Worker logs upload failures and continues with the default cover URL.
- OpenRouter generation failures keep the existing skip behavior.

## Tests

Add focused tests for:

- Cloudinary upload request shape, authentication, multipart fields, and response parsing.
- Cloudinary non-2xx error handling.
- Worker selection behavior:
  - Cloudinary URL wins when upload succeeds.
  - Existing repo asset fallback still works when Cloudinary is not configured and asset base URL is configured.
  - Default cover remains when upload fails.
- Config loading for the new Cloudinary env vars.
